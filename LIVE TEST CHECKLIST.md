# First device / live-table test

Use the extracted development copy. Record failures and export the session for review.

1. **Launch and setup:** run the OS setup and backup launcher. Save rules and your seat. Close/reopen; confirm settings persist. Verify chip icon, window fit, dark/light/compact, keyboard shortcuts and always-on-top overlay.
2. **Reference fixture:** load `Developer/fixtures/actual-table.png` through Test screenshot. Wait for automatic alignment and confirmation; no drawing or checkbox is required. Expect seat 4 A♣ Q♦ 3♣ = 14, seat 3 Q♣ 9? = 19, dealer 8♠, six counted cards, RC −2. Repeated scans must keep six cards. The active panel must not contribute another three cards.
3. **Corrections:** replace seat 4 with A Q 8. RC should fall by one while the unique count stays six. Undo should restore the prior hand/count and pause scanning. Test the manual lock and unlock behavior. This verifies local ledger controls; the reference is not an independent detector benchmark.
4. **Capture:** connect the actual SportsBetting browser window. Confirm the live image is identical to the browser. Wait for TABLE: AUTO-ALIGNED, then compare the detected occupied seats, totals and dealer against the actual table. Resize the window; alignment should recover automatically.
5. **Live-feed editing:** toggle outlines. Click Edit outlines and move/resize a player and a small total badge directly on the feed. Confirm video continues but counts pause. Done editing must preserve the count and resume only if previously scanning. Cancel must restore the old boxes. Verify adjustments survive restart and follow automatic window rescaling. Check edges, letterboxing, high-DPI, touch cancellation, arrow/Shift-arrow nudges and reset selected/all. Test a hit extending past the old boundary; its crop should expand. An edge-clipped card or shared occupied area must be red and under review.
6. **Round 1:** start at a known new shoe if you need a meaningful remaining-shoe estimate. Reset count explicitly. Watch the dealt cards; compare the detected sequence, seat number and total before relying on the action. If VERIFYING persists, capture a manually authorized fixture for development and correct the hand. Do not lower confidence to hide an error.
7. **Round transitions:** verify a clear table lasting at least three observations and 1.5 seconds advances to the next hand once cards return. An unrelated/hidden capture must not count as a clear table. If scanning missed the transition, use Next hand only after old cards disappear. Ensure identical hands in consecutive rounds count twice, but static cards in one round count once. Never use New shoe just because one hand ended.
8. **Dealer reveal:** verify the original up-card remains the up-card when the hole card appears on its left. A finished dealer hand should enter history after the round transition; a lone up-card must not.
9. **Timing:** after OCR warm-up, record wall-clock time from the selected player's final needed card appearing to a stable move across at least 20 varied hands. Compare the app's scan-time field, but do not substitute fixture timings for live latency. Check busy/paused behavior and make sure cancelling a scan does not commit stale results.
10. **Difficult cases:** test three-plus-card stacks, multiple aces, repeated ranks, all occupied seats, partially covered cards, transient animations, background changes and loss of capture. Uncertain reads must retain the old count and withhold the move.
11. **Splits/doubles/surrender:** start with a verified pair. After splitting, verify two separate stacks, independent total crops and separate rows. The original pair must move into the child hands: two cards become four after one new card per hand, never six. Hit one split; only its new card should enter the count. Test missing badges and a third stack: both hands must remain under review. Use Manual Correction with two hands separated by / if necessary. Record each observed split outcome separately. Confirm doubled and surrender flags from the table. Review outcome must remain UNKNOWN when the final dealer hand is unavailable.
12. **Results:** verify WIN, LOSS, PUSH, natural blackjack versus three-card 21, and surrender. Confirm result once per hand; duplicate confirmations must be rejected. Check wins/(wins+losses), with pushes/surrenders excluded.
13. **New shoe:** test manual reset and undo. There is no automatic shuffle prompt in this version. Cancel must keep the count. The app must never reset merely because cards disappear.
14. **Export:** save both CSV and JSON and inspect ranks, RC/TC, recommendations, correction events and result labels. Close only after exporting if you want to retain the session.
15. **Platforms/scaling:** repeat capture/automatic-alignment tests on Windows and Mac, at 1080p/1440p/4K and common display/browser scales. Test target-platform installer/portable builds, signing and permissions separately before distribution.

Remaining acceptance work: unseen-image accuracy, rank/suit template coverage, live split-layout coverage, automatic outcome detection, clear-table transition robustness, real browser UI layout, native capture/overlay, update network handling, and signed standalone packaging. This build is not production validated.
